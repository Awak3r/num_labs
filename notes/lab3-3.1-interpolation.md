# ЛР 3.1 — Интерполяция: Лагранж и Ньютон (вариант 3)

## Постановка

Вариант 3: f(x) = tg(x), x* = 3π/16 ≈ 0.58904862, по 4 узла в двух наборах.
В файлах `data/interpolation_a.txt` / `_b.txt` — только xᵢ и x*;
значения yᵢ программа вычисляет сама: yᵢ = tg(xᵢ) (funcs.Tan), не хардкод.

```
набор а:  x = 0,  π/8 (0.3927), π/4  (0.7854), 3π/8 (1.1781)
набор б:  x = 0,  π/8 (0.3927), π/3  (1.0472), 3π/8 (1.1781)
          y = tg(x):  0, 0.41421, 1 / 1.73205, 2.41421
```

Разница наборов — только ВТОРОЙ внутренний узел: π/4 против π/3.
Цель ТЗ — увидеть, как расположение узлов относительно x* влияет на
погрешность интерполяции.

---

## Единственность (вопрос с защиты №1)

Через n+1 узлов (у нас 4 узла) проходит **ровно один** многочлен степени ≤ n.
Почему: интерполяция в узлах — n+1 линейное уравнение на n+1 коэффициент.
Если бы существовали два многочлена P и Q степени ≤ 3 с одинаковыми значениями
в 4 точках, разность D = P−Q была бы многочленом степени ≤ 3 с 4 корнями,
значит D ≡ 0.

Следствие: **L(x) ≡ N(x)** — это один и тот же многочлен в разных базисах.
В выводе |L(x*)−N(x*)| ~ 1e-16 — только ошибки округления float.

## Многочлен Лагранжа

```
       3   yᵢ·(x−xⱼ)·(x−x_k)·(x−x_m)
L(x) = Σ  ────────────────────────────────      (j,k,m ≠ i — три других узла)
      i=0      (xᵢ−xⱼ)·(xᵢ−x_k)·(xᵢ−x_m)
```

Идея: базис ℓᵢ(x) равен 1 в «своём» узле xᵢ и 0 во всех остальных —
тогда комбинация Σ yᵢ·ℓᵢ автоматически проходит через все узлы.

В коде (`lab3/interpolation/interpolation.go:69–88`): слагаемое построено не через
деления, а честным произведением: для каждого i скобочная часть
(x−xⱼ) умножается последовательно (`polyMulShift`, interpolation.go:114 —
умножение текущего базиса на (x − root): старшие +1 степень, младшие −root·c),
затем делится на масштаб Π(xᵢ−xⱼ) и прибавляется с весом yᵢ.
Результат — **канонические коэффициенты** (по возрастанию степени) + строка Form.

Проверка прохода через узлы тривиальна: L(xᵢ) = yᵢ по построению.

## Разделённые разности и многочлен Ньютона

Рекуррентное определение (`interpolation.go:17–31`, d[k][i] = f[xᵢ..xᵢ₊ₖ]):

```
f[xᵢ]      = yᵢ
f[xᵢ..xⱼ]  = ( f[xᵢ₊₁..xⱼ] − f[xᵢ..xⱼ₋₁] ) / (xⱼ − xᵢ)
```

Таблица (набор а, реальные числа из results.txt, строки 12–16):

```
         x = 0        0.3927       0.7854       1.1781
k=0:     0.000000     0.414214     1.000000     2.414214
k=1:     1.054786     1.491693     3.601265
k=2:     0.556287     2.685991
k=3:     1.807749
```

Форма Ньютона:

```
N(x) = f[x₀] + f[x₀,x₁]·(x−x₀) + f[x₀,x₁,x₂]·(x−x₀)(x−x₁)
              + f[x₀..x₃]·(x−x₀)(x−x₁)(x−x₂)
```

Для набора а (results.txt:18):

```
N(x) = 0 + 1.05479·(x−0) + 0.556287·(x−0)(x−0.3927)
             + 1.80775·(x−0)(x−0.3927)(x−0.7854)
```

Смотрите: **первый коэффициент формы Ньютона (диагональ таблицы — f[x₀..xₖ])
совпадает со старшим коэффициентом L** — 1.807749 в обоих представлениях.
Это ещё одно проявление единственности.

Вычисление N(x*) — схема Горнера для формы Ньютона
(`EvalNewton`, interpolation.go:60–67):

```
res = c₃;
res = res·(x−x₂) + c₂;
res = res·(x−x₁) + c₁;
res = res·(x−x₀) + c₀        →  N(x)
```

Почему Ньютон практичнее Лагранжа: добавление нового узла x₄ требует только
нового столбца таблицы и одного слагаемого; коэффициенты уже посчитанные не
меняются. У Лагранжа пересчитывается всё.

## Погрешность — центральный блок варианта

Остаточный член теории:

```
R(x) = f⁽⁴⁾(ξ)/4! · ω(x),      ω(x) = (x−x₀)(x−x₁)(x−x₂)(x−x₃),
ξ ∈ (min(xᵢ, x), max(xᵢ, x))
```

и x* в обоих наборах одни и те же — отличаются только узлы, значит
отличается только множитель ω(x*) и положение ξ.

Считаем ω(x*) в точке x* = 3π/16 = 0.58905 руками:

```
набор а:  ω_a = (0.58905−0)(0.58905−0.39270)(0.58905−0.78540)(0.58905−1.17810)
              = 0.58905 · 0.19635 · (−0.19635) · (−0.58905)
              = +(0.58905²)·(0.19635²) = 0.013377

набор б:  ω_b = 0.58905 · 0.19635 · (−0.45815) · (−0.58905)
              = 0.031212
```

ω_b/ω_a ≈ 2.33 — из-за сдвига среднего узла на π/3 произведение расстояний
до x* выросло в 2.3 раза. Фактические погрешности (results.txt:22, :45):

```
набор а:  |f(x*)−L(x*)| = 0.02357
набор б:  |f(x*)−L(x*)| = 0.08293     (отношение 3.52)
```

Отношение больше 2.33, потому что ξ тоже разное: из формулы обратного хода
|f⁗(ξ_a)| ≈ 42.3 и |f⁗(ξ_b)| ≈ 63.6 — у набора б ξ сдвинулся в зону, где
tg⁗ больше (на правом крае отрезка она растёт как sec⁴·8·..., у x близких
к π/3 производные уже вполовину выше). Оба фактора работают в одну сторону.

Выводы для защиты (и по ТЗ):

- набор **а** равномернее «окружает» x* → меньше Π расстояний → точнее;
- минимизация ω — расстановка узлов по Чебышеву (проекции равномерных точек
  полуокружности на ось x),
  классическая тема «почему равномерные узлы не оптимальны»;
- при увеличении n с равномерными узлами погрешность может расти — феномен
  Рунге (ассоциируется с той же темой).

## Вопросы с защиты (короткие ответы)

- **Что интерполируем?** tg(x), x*=3π/16, 4 узла, два набора — отличается
  один средний узел.
- **Единственность?** По пунктам выше: 4 линейных условия, det ≠ 0;
  поэтому L ≡ N (числа совпали до 1e-16).
- **Разделённые разности?** Рекуррентная формула + таблица; диагональ = коэфф
  формы Ньютона.
- **Ньютон vs Лагранж?** Один многочлен, разные базисы; Ньютон допускает
  добавление узла без пересчёта, вычисляется по Горнеру.
- **Откуда погрешность?** R = f⁗(ξ)/24·ω(x*); ω_a = 0.0134, ω_b = 0.0312 →×2.33,
  ξ дополнительно усиливает, итог ×3.52.
- **Как улучшить?** Узлы ближе/симметричнее к x*, Чебышев, больше узлов
  (осторожно: Рунге).
- **yᵢ из файла?** Нет — в файле только x, x*; y = tan(x) считает программа.
- **x* вне отрезка?** Программа не проверяет; экстраполяция — резкий рост |R|.
